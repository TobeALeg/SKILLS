# Mini Web App 场景评价标准

山途远智团队在评估「要不要做这个小微应用」时，用这套框架打分。满分 5 分制，总分加权后排优先级。

## 六个评价维度

### 1. 传播适配度（权重 25%）

> 这个东西往外抛的时候，好不好抛？

| 分数 | 标准 |
|------|------|
| 5 | 一句话就能说清楚价值，适合做文章标题/视频 hook/广告素材，受众看到就想点 |
| 4 | 需要 2-3 句话解释，但解释完之后吸引力强 |
| 3 | 需要配合场景说明才能让人理解为什么要用 |
| 2 | 只有已经在找解决方案的人才会感兴趣 |
| 1 | 很难用一段话让陌生人产生点击欲望 |

判断方法：试着写一条朋友圈/一个视频开头/一句广告文案。如果写不出让人想点的那句话，说明传播适配度不够。

加分项：

- 能自然嵌入已有内容（文章末尾 CTA、视频描述区链接）
- 结果本身可以被用户截图/转发（自带二次传播）
- 话题有时效性或争议性（蹭得上热点）

### 2. 即时感知价值（权重 20%）

> 用户 30 秒内能不能感受到「这东西对我有用」？

| 分数 | 标准 |
|------|------|
| 5 | 输入一个品牌名，立刻看到有冲击力的结论，不需要等、不需要学 |
| 4 | 1-2 步操作后看到有价值的输出，体验流畅 |
| 3 | 需要 3-5 分钟才能看到价值，但过程不无聊 |
| 2 | 需要上传数据或等待较长时间才能体验 |
| 1 | 需要专人讲解才能理解输出的意义 |

判断方法：让一个不了解我们的消费品从业者试用，观察他/她多快说出「哦这个有意思」。

### 3. 线索获取能力（权重 20%）

> 用完之后我们能拿到什么？

| 分数 | 标准 |
|------|------|
| 5 | 自然获取品牌名 + 联系方式 + 明确需求意向，用户觉得留信息是合理的 |
| 4 | 获取品牌名 + 联系方式，用户愿意留但没有强动机 |
| 3 | 只能获取品牌名或行业信号，联系方式需要额外引导 |
| 2 | 用户可以匿名使用，留资率低 |
| 1 | 没有自然的留资节点，强制要求会导致流失 |

判断方法：在体验流程中，「留联系方式」这个动作是否出现在用户最想看更多的那个时刻？

### 4. 技术可行性（权重 15%）

> 能不能做得到？做到什么程度？

| 分数 | 标准 |
|------|------|
| 5 | 现有技术栈 + 已有数据即可实现，1-3 天上线 |
| 4 | 需要少量新开发或接入一个新数据源，1 周内可上线 |
| 3 | 需要中等开发量或新的 AI prompt 工程，2 周内可上线 |
| 2 | 需要较大开发投入或依赖尚未验证的技术方案 |
| 1 | 技术上有硬障碍（数据不可得、精度不够、成本过高） |

判断方法：

- 数据从哪来？是否已有管道？
- AI 输出质量能否达到「不丢人」的水平？
- 是否需要实时计算还是可以预生成？

### 5. 交付质量可控度（权重 10%）

> 做出来的东西，质量能不能稳定在「不翻车」以上？

| 分数 | 标准 |
|------|------|
| 5 | 输出结构化、可校验，翻车概率极低 |
| 4 | 大部分情况输出质量稳定，偶尔需要人工审核 |
| 3 | 需要设计兜底机制（如：数据不足时降级展示） |
| 2 | 输出质量波动大，需要逐条人工审核才能发布 |
| 1 | 经常出现明显错误或无意义的输出 |

判断方法：用 10 个不同品牌跑一遍，看有几个结果可以直接发给客户。

### 6. 后续转化路径（权重 10%）

> 从「用了一下」到「想跟我们深聊」有多远？

| 分数 | 标准 |
|------|------|
| 5 | 体验本身就是服务的缩影，用户自然想要「完整版」 |
| 4 | 体验结束后有清晰的下一步（预约、看完整报告、对比竞品） |
| 3 | 需要额外沟通才能让用户理解我们还能做什么 |
| 2 | 体验和付费服务之间有认知断层 |
| 1 | 用户觉得免费版已经够了，没有付费动机 |

判断方法：用户体验完之后，是否会主动问「那我自己的品牌呢？」

## 快速评分表

| 维度 | 权重 |
|------|------|
| 传播适配度 | 25% |
| 即时感知价值 | 20% |
| 线索获取能力 | 20% |
| 技术可行性 | 15% |
| 交付质量可控度 | 10% |
| 后续转化路径 | 10% |

## 决策规则

- 加权总分 >= 4.0：优先做，排进本周计划
- 3.0 - 3.9：值得做，排进两周内计划
- 2.0 - 2.9：暂缓，除非某个单项是 5 分（说明有独特价值但需要解决短板）
- < 2.0：不做

## 一票否决项

以下任一条件成立，无论总分多高都不做：

- 技术可行性 <= 2
- 传播适配度 <= 2 且 即时感知价值 <= 2
- 交付质量可控度 <= 2

## 示例：品牌消费者洞察报告

| 维度 | 得分 | 理由 |
|------|------|------|
| 传播适配度 | 5 | 「你品牌的消费者在用什么词说你？」一句话就能做文章标题 |
| 即时感知价值 | 4 | 打开就能看到结论和原话引用，但需要先选品牌（非实时生成） |
| 线索获取能力 | 5 | 看完 2 条想看完整版，自然留微信，品牌名 + 联系方式 + 意向都拿到了 |
| 技术可行性 | 5 | 已有完整管道，新品牌 30 分钟出报告 |
| 交付质量可控度 | 4 | 大部分品牌输出质量稳定，语料不足时需要降级 |
| 后续转化路径 | 5 | 「这是公开数据版，接上你的内部数据能看到更多」天然升级 |
| 加权总分 | 4.7 | 优先级最高 |

## 场景 brainstorm 模板

```text
场景名称：___
一句话描述：___（如果这句话写不出来，传播适配度大概率 <= 3）
目标用户：___（谁会用？什么时候用？）
输入：用户需要提供什么？
输出：用户能看到什么？
传播 hook：这个东西怎么往外抛？（写一条朋友圈试试）
技术依赖：需要什么数据/API/模型能力？
留资时机：在哪个节点让用户留信息最自然？
```
